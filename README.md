# Dependency Graph Visualizer (Вариант 28)

## Общее описание
CLI-утилита для визуализации графа зависимостей пакетов формата Java (Maven).
Разрабатывается в рамках дисциплины «Конфигурационное управление». Проект разбит на этапы, описание которых приведено ниже.

## Сборка и запуск
*   **Сборка проекта:** `.\gradlew build`
*   **Запуск приложения:** `.\run.bat [опции]`

---

## Этап 1. Минимальный прототип с конфигурацией
**Описание:**
Приложение считывает параметры из командной строки, валидирует их и выводит в формате «ключ-значение». Реализована обработка ошибок для всех параметров.

**Поддерживаемые опции:**
*   `-p <package_name>` — Имя анализируемого пакета (обязательный).
*   `-r <url_or_path>` — URL-адрес репозитория или путь к файлу тестового репозитория (обязательный).
*   `-d <number>` — Максимальная глубина анализа зависимостей (обязательный, целое число > 0).
*   `-t` — Флаг включения режима тестирования (опциональный).

**Примеры использования:**
```bat
# Успешный запуск
.\run.bat -p org.apache.commons -r https://repo.maven.apache.org/maven2 -d 3

# Обработка ошибки (неверный тип данных)
.\run.bat -p test -r url -d abc
```

## Этап 2. Сбор данных
**Описание:**
Реализована логика получения прямых зависимостей пакета Maven. Программа формирует URL к `.pom` файлу на основе координат пакета, скачивает его с указанного репозитория и извлекает информацию о зависимостях из тега `<dependencies>` с помощью встроенного XML-парсера Java. Сторонние библиотеки для работы с зависимостями не используются.

**Примечание:**
Поскольку в конфигурации не предусмотрено отдельного поля для версии пакета, параметр `-p` должен передаваться в следующем формате: `groupId:artifactId:version`.

**Пример использования:**
```bat
.\run.bat -p org.apache.commons:commons-lang3:3.12.0 -r https://repo.maven.apache.org/maven2 -d 3
```

## Этап 3. Основные операции
**Описание:**
Реализовано построение графа зависимостей с учетом транзитивности с использованием алгоритма BFS (поиск в ширину) с рекурсией. Программа имеет защиту от циклических зависимостей (повторно посещенные узлы не обрабатываются). Глубина анализа ограничивается параметром `-d`.

**Режим тестирования (`-t`):**
Если указан флаг `-t`, программа не обращается к интернету, а читает граф из локального файла. Формат файла: `Пакет1 -> Пакет2` (каждая связь с новой строки). Параметр `-r` в этом случае должен содержать путь к этому файлу.

**Пример использования (тестовый режим):**
Создайте файл `test-repo.txt`:
```text
A -> B
B -> C
C -> A
```

Запустите приложение с флагом -t:
```bat
.\run.bat -p A -r test-repo.txt -d 3 -t
```
